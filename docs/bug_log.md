bug was: the design (RTL), the testbench, a test program, or a difference between the

## Coverage items that turned out to be impossible

* **Load-use stall in the same cycle as a fetch wait**: the core only fetches when the ID
  slot will be free; a load-use stall keeps ID full, so no fetch is ever outstanding then.
* **Flush while the divider is busy**: while a divide runs EX stalls, MEM receives only
  bubbles, and no older instruction is left to trap. Now an assertion (`a_no_flush_div_busy`)
  instead of a coverage bin; "flush in the cycle a divide starts" is covered.

Both were found as coverage holes, and the reason was confirmed from the design before
the bins were changed (see docs/testplan.md).

## Spike behaviour checked before writing the spec

These were found by running small probe programs on Spike before any RTL, so they became
spec decisions instead of bugs: FENCE.I executes (even without Zifencei in the ISA string);
`mtvec` bit 0 is writable; `mconfigptr` (0xF15) exists; a trapping instruction is not
logged as a commit; writing `mip` makes Spike take a timer interrupt; Spike runs a few
instructions after the `tohost` store.
